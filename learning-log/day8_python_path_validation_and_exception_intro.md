### 1. 布尔值

```python

```

- `True`：条件成立；
- `False`：条件不成立；
- `if` 根据布尔结果选择执行路线。

### 2. Path 与文件存在检查

学习：

```python
from pathlib import Path

file_path = Path("本地成绩文件.xlsx")
file_path.exists()
```

已理解：

- 文件名属于字符串，必须放在英文引号中；
- `.xlsx` 前的英文句点属于文件名的一部分；
- `Path` 使用前必须先导入；
- `exists()` 返回布尔值；
- 相对路径只在当前工作目录中查找；
- `Path.cwd()` 可以查看当前工作目录；
- 文件确实存在但 `exists()` 返回 `False` 时，应优先检查程序查找的目录是否正确。

今晚已经使用本地完整路径成功找到并读取成绩文件。真实路径不写入学习记录。

def → 定义函数的 Python 关键字
df  → 常用的 DataFrame 变量名

df = pd.read_excel(file_path)

### 4. 必要列检查

学习：

```python
"英语" in df.columns
```

能够解释：

- `df.columns` 是表格的列名；
- `in` 检查目标是否属于这一组列名；
- 结果是 `True` 或 `False`；
- “英语”列不存在时，应停止相关分析并给出明确提示。

已经分别验证列存在和列不存在两条分支。

### 5. 有效数据检查

学习：

```python
english_scores = df["英语"].dropna()
english_scores.empty
```

能够区分：

- `english_scores = ...`：准备并保存数据；
- `english_scores.empty`：判断去掉空值后是否为空；
- 有效数据为空时应停止分析；
- 当前练习数据通过有效数据检查。

### 6. 多层 if / else 与缩进

已成功组合三层输入验证：

```text
文件存在？
├─ 否 → 提示检查文件名
└─ 是 → 读取文件
         └─ 有“英语”列？
            ├─ 否 → 提示检查表头
            └─ 是 → 去掉空值
                     └─ 有效成绩为空？
                        ├─ 是 → 提示没有有效数据
                        └─ 否 → 数据检查通过
```

缩进理解：

- 冒号表示开始新的代码块；
- 向右缩进表示进入下一层；
- 相同缩进表示属于同一个代码块；
- 向左退回表示离开当前代码块；
- `else` 必须与对应的 `if` 对齐；
- 文件检查不通过时，内部列检查和数据检查不会执行。

当前完整验证程序已成功输出：

```text
文件读取成功
英语列检查通过
英语数据检查通过
```

## 二、常见错误与已纠正内容

今晚出现并已解释：

- 中文冒号、中文括号不能代替 Python 代码中的英文符号；
- 文件名未加引号导致 `SyntaxError`；
- 未导入 `Path` 导致 `NameError`；
- 相对路径查错文件夹导致 `exists()` 返回 `False`；
- 把 `df` 与 `def` 混淆；
- 把赋值语句误当成判断条件；
- 将 `columns` 写成独立名称，而不是 `df.columns`；
- 没有新代码块却额外缩进会产生 `IndentationError`；
- `else` 的归属由缩进层级决定。

## 三、try / except 完成情况

已经理解异常的基本执行规则：

> `try` 中某一行发生异常时，会立即跳过该行之后尚未执行的 `try` 内容，转入 `except`。异常处理结束后，可以继续执行 `try / except` 外面的代码。

已经能够区分：

```text
if         → 处理可以提前判断的正常条件
try/except → 处理执行操作时才知道会不会发生的异常
```

例子：

- 文件是否存在、英语列是否存在、数据是否为空：优先使用 `if`；
- Excel 存在但损坏、加密、格式不正确或无法读取：使用 `try / except`。

已经完成：

- 使用正确 Excel 验证 `try` 的成功路线；
- 使用不存在的测试路径触发 `FileNotFoundError`；
- 使用真实存在的 PNG 文件触发其他读取异常；
- 使用 `as error` 保存并显示具体技术原因；
- 理解具体异常应放在前面，宽泛的 `Exception` 放在最后兜底；
- 理解 `if` 与 `try` 的核心区别：`if` 根据布尔值选择路线，`try` 根据实际操作是否抛出异常选择路线；
- 理解 `try / except / else`：只有 `try` 没有异常时才进入 `else`；
- 将列名检查和有效数据检查接入 `try` 的成功分支；
- 将实验变量 `test_df` 统一恢复为正式变量 `df`。

最终程序已通过三类读取测试：

```text
正确 Excel → 读取成功，继续检查表格
文件不存在 → 中文提示检查路径
文件存在但不是 Excel → 中文提示无法读取，并保留技术原因
```
