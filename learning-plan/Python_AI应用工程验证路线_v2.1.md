> 更新日期：2026-08-16

> 核心目标：不是尽快“学完技术栈”，而是在较短周期内用真实项目验证——是否喜欢工程实现、是否能逐步独立完成功能、以及“教育经验 × 数据 × AI”是否能形成可用产品。

## 一、为什么从 v2 调整到 v2.1

v2 的方向是对的：Day 1–6 已经证明可以继续学 Python / pandas，下一阶段应从“会分析数据”转向“能组织程序、连接 AI、做出可用工具”。

但 v2 还有三个需要调整的地方：

1. **不能把已经形成的教育数据主线突然切断。** Day 6 的学情报告已经有真实产物，下一步应该把它工程化，而不是另起炉灶。
2. **AI API 应更早进入。** 如果核心问题是验证“是否适合 AI 应用工程”，就不应该先花很长时间补完 SQL 等外围知识再碰 AI。
3. **SQL、复杂框架、长期数据库应按产品需要进入。** 没有真实需求时先不学；当“多次考试历史”“学生长期画像”真正需要持久化时再学，理解会更牢。

因此 v2.1 的顺序改成：

```text
完成当前学情项目闭环
→ 函数化 / 程序结构
→ 文件与异常
→ 最小工程目录 + Git
→ API / JSON
→ LLM API
→ Streamlit 做成可用工具
→ 再按需要补 SQL / 数据库
→ 深化教育 AI 产品
```

# 三、教学方式同步调整

从 Day 7 开始，不采用“老师给完整代码 → 学生照抄”的方式。

默认流程：

```text
真实问题
→ 先说清输入 / 输出 / 结构
→ 学生先写
→ 卡住时只给一个小提示
→ Debug
→ 再总结可复用规律
```

对于完全没学过的新语法，可以先给最小示例；但随后必须有一次独立改写或迁移任务。

每一课至少回答三个问题：

1. 这个技术解决什么真实教育问题？
2. 哪一部分应该交给 AI，哪一部分必须由人判断？
3. 今天留下了什么可运行、可展示、可复用的职业证据？

## Day 7B：函数 `def`——把 Day 6 顺序代码拆开

学习：

- 为什么写函数；
- 参数；
- `return`；
- 局部变量；
- 一个函数只负责一件事。


```text

```

### 验收

# 六、阶段 B：尽早验证 AI 应用工程（约 6–10 小时）

## Day 11：第一次让自己的 Python 程序调用 LLM

目标：完成真正的跃迁：

> 从“在 ChatGPT 里使用 AI” → “自己的程序把数据交给 AI 并接回结果”。

输入不要传真实学生身份信息，只传匿名统计指标，例如：

```json
{
  "valid_count": 69,
  "mean": 40.1,
  "median": 38.4,
  "score_bands": {"30-40": 21, "40-50": 16}
}
```

让 AI 输出：

- 数据事实摘要；
- 需要进一步验证的推断；
- 教学建议。

### 验收

不用人工复制粘贴，Python 能完成“统计数据 → LLM → 返回文本”。

---

## Day 12：结构化 AI 输出 + 基础可靠性

让 AI 返回 JSON，而不是随意一大段文字：

```json
{
  "facts": [],
  "inferences": [],
  "suggestions": []
}
```

学习：

- 结构化输出；
- 字段检查；
- 超时 / 失败；
- 最小重试；
- 为什么不能把 AI 推断冒充数据事实。

### 验收

程序可以稳定读取 AI 返回的多个字段；错误格式时能发现问题。

# 八、第一次工程适配检查：从现在起约 20–30 小时

不要等到 100 小时才第一次判断。

完成 v0.1 后记录四组证据：

## 1. 工程兴趣

- 新鲜感下降后，是否仍想继续改功能？
- Debug 时，是单纯烦躁，还是有“想把它搞明白”的冲动？
- 是否会主动想到下一版功能？

## 2. 独立度

- 是否开始能先设计结构再写代码？
- 是否能独立写一部分函数？
- 报错时是否先读错误信息，而不是立刻等答案？
- 是否能改动已有代码而不完全依赖逐行指导？

## 3. 产品感

- 是否会想到“老师实际怎么用”？
- 是否会主动质疑指标是否有教育意义？
- 是否能区分数据事实、推断和建议？

## 4. 持续成本

- 工作后的学习是否长期可维持？
- 对 Debug、文档、环境配置这些“没那么酷”的部分接受度如何？

这个阶段只回答：

> **我是否值得继续投入到下一阶段？**

不急着做辞职、考研、转行等最终决定。

# 十一、RAG / Agent / 框架什么时候学

只有出现明确产品问题时才进入。

例如：

- 需要从大量校本资料中检索再回答 → 再学 RAG；
- 一个任务真的需要多个工具自主协作 → 再考虑 Agent；
- 自己写的 API / LLM 流程开始重复、难维护 → 再评估框架。

前期不以“会 LangChain / 会 Agent”作为能力证明。

真正的证明是：

> 能定义问题、设计数据流、写出可运行程序、处理错误、验证输出、让真实用户完成任务。

# 十二、时间检查点

## 约 10–15 小时后

看：

- 函数和模块是否开始形成结构感；
- 是否愿意继续 Debug；
- 是否能改动现有项目。

不做职业决定。

## 约 25–35 小时后

要求至少有一个可运行的学情助手 v0.1。

判断：

> 工程实现本身是否让我有持续兴趣？

## 约 50–60 小时后

看：

- 独立完成功能的比例是否上升；
- 是否愿意读文档、处理边界情况；
- 是否喜欢“产品迭代”而不只是写几行代码；
- 教育领域是否仍然是优势和兴趣来源。

## 约 80–120 小时后

再做较正式路线判断：

### A. 工程兴趣强 + 教育领域仍有吸引力

优先考虑：教育 AI / 教育科技 / AI 应用工程 / 相关硕士方向。

### B. 工程兴趣强 + 不想绑定教育

再扩大到通用 AI 应用工程 / 软件工程，并根据目标岗位反推补计算机基础。

### C. 工程兴趣一般 + 仍愿意教学

把 AI 工具作为教学与教研效率杠杆，同时重新比较学校、市编等路径。

### D. 工程兴趣弱 + 教育兴趣也弱

重新探索，不为了已经投入的时间强行坚持。

# 十三、作品与隐私规则

真实班级数据只在本地用于学习和验证。

公开作品必须使用：

- 合成数据；或
- 彻底匿名化数据；或
- 公开数据。

公开仓库不得包含：

- 学生姓名；
- 宿舍、教室等可识别信息；
- API key；
- 真实工作文件中不必要的敏感字段。

Project 01 的公开版本后续应重建一份 `sample_data.xlsx`，而不是直接提交真实 8 班文件。
