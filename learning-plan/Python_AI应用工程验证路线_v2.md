> 建立日期：2026-08-16  
> 适用对象：凃晨霄  
> 目的：在不盲目转行、不平均分配精力的前提下，用约 80–120 小时真实验证自己是否适合 AI 应用工程，并为“考研 / 市编 / 技术转向”提供证据。

## 一、为什么升级原计划

原《Python_数据分析长期教学规划》以“Python + pandas 数据分析入门”为主，适合最初验证对数据分析是否有兴趣。

截至 Day 6，已经完成：

- Python 基础变量、列表、字典、条件判断；
- pandas / DataFrame 基础；
- Excel 读取、缺失值、重复值和逻辑异常检查；
- 条件筛选、排序、分组与描述统计；
- `pd.cut()`、`value_counts()` 等成绩分布分析；
- 从数据现象形成教学判断；
- `if / else`、f-string、字典；
- 自动生成英语学情文字报告；
- `with open()` 保存文件；
- Jupyter + GitHub 基本学习记录流程。

当前新的核心问题已经不再是：

> “我能不能学一点 Python / 数据分析？”

而是：

> **“我是否适合长期做 AI 应用工程，并能把教育经验转化成真正的软件产品？”**

因此从 Day 7 开始，课程从“数据分析路线”转为“工程能力验证路线”。

# 二、总原则

## 1. 项目驱动，不刷教程

每学一个知识点，都尽量立即进入真实项目。

顺序不是：

```text
先把 Python 全学完
→ 再学数据库
→ 再学 API
→ 最后做项目
```

而是：

```text
项目遇到问题
→ 学最需要的知识
→ 立即使用
→ 留下可运行成果
```

## 2. 不追求“学完”，追求“能搭出来”

判断标准不是记住多少函数，而是能否：

- 看懂程序结构；
- 把大问题拆成模块；
- 独立查错误；
- 修改已有代码；
- 解释代码为什么这样写；
- 从零做出一个可以工作的版本。

## 3. 暂不追热点框架

前期不优先：

- LangChain；
- 向量数据库；
- 复杂 RAG；
- 多 Agent；
- 模型微调；
- 深度学习底层训练。

先把以下基础链条跑通：

```text
Python
→ 函数
→ 模块
→ 文件
→ 异常
→ Git
→ JSON / API
→ SQL
→ LLM API
→ 简单 Web UI
→ 部署 / 重构
```

只有基础扎实后，再判断是否需要 RAG、Agent 等工具。

# 三、阶段 A：Python 工程基础（约 12–18 小时）

目标：从“Notebook 里顺序写代码”升级到“能组织一个小程序”。

## Day 7：函数 `def`

核心内容：

- 为什么要写函数；
- 参数与返回值；
- 局部变量；
- 一个函数只负责一件事。

直接重构 Day 6 报告代码：

```python
calculate_summary()
generate_advice()
generate_report()
save_report()
```

### 验收

能把一坨顺序代码拆成 3–5 个职责清晰的函数，并说明每个函数的输入和输出。

---

## Day 8：文件路径 + JSON / CSV + 异常处理

核心内容：

- `pathlib.Path`；
- CSV / JSON 基础；
- `try / except`；
- 用户文件不存在、格式错误、列名不对时怎么办。

### 小任务

让程序做到：

```text
读取成绩文件
→ 检查文件是否存在
→ 检查关键列是否存在
→ 出错时给出可理解提示
```

### 验收

程序面对错误输入不会直接“炸掉”，而是能够解释发生了什么。

---

## Day 9：模块与项目目录

从单 Notebook 转成：

```text
english_ai_assistant/
├── data/
├── reports/
├── src/
│   ├── data_cleaning.py
│   ├── analysis.py
│   └── report.py
├── main.py
└── README.md
```

学习：

- `.py` 文件；
- `import` 自己写的函数；
- 模块之间如何协作；
- `if __name__ == "__main__":` 初步理解。

### 验收

能够把原来的分析流程拆进多个文件，并由 `main.py` 调用。

---

## Day 10：Git 真正进入工程流程

学习：

- 工作区 / 暂存区 / commit 的基本概念；
- 小步提交；
- commit message；
- README；
- `.gitignore`；
- 为什么不要把密钥提交到 GitHub。

同时认识：

- Python 虚拟环境；
- `pip`；
- `requirements.txt`。

### 验收

项目可以被另一个人 clone 后，根据 README 重建环境并运行。

# 四、阶段 B：数据库 + API + AI（约 18–25 小时）

目标：让程序第一次拥有“记忆”和“外部能力”。

## Day 11：SQL / SQLite 基础

只学项目立即需要的内容：

```sql
CREATE TABLE
INSERT
SELECT
WHERE
ORDER BY
GROUP BY
UPDATE
```

不单独刷大量 SQL 题。

### 项目数据结构

至少设计：

```text
students        学生
exams           考试
scores          成绩
writing_records 作文记录（后续）
```

### 验收

能够把一次分析结果保存到 SQLite，并在下一次运行时重新读取。

---

## Day 12：数据库关系 + JOIN

理解：

- 为什么不能把所有信息塞进一张表；
- 主键；
- 外键的直觉；
- 一对多；
- `JOIN`。

### 验收

可以查询：

> 某学生过去几次英语考试的成绩变化。

---

## Day 13：HTTP / API / JSON

理解：

```text
程序
→ 发请求
→ API
→ 返回 JSON
→ Python 读取
```

学习：

- request / response 的基本概念；
- status code；
- headers / body 的直觉；
- JSON 与 Python 字典之间的关系；
- 环境变量保存 API key。

### 验收

能调用一个简单外部 API，并把返回结果整理成 Python 数据。

---

## Day 14：第一次让自己的程序调用大模型

目标：完成关键跃迁——

> 从“在 ChatGPT 里使用 AI”到“自己的程序调用 AI”。

学习：

- prompt 在程序里是什么；
- 输入 / 输出；
- token 与成本意识；
- API key 安全；
- 超时、失败、重试的基础概念。

### 小任务

把班级统计指标交给模型，生成：

- 数据事实摘要；
- 教学建议；
- 明确标注“推断”与“事实”。

### 验收

AI 输出不再靠人工复制粘贴，完整进入 Python 流程。

---

## Day 15：结构化 AI 输出

目标：避免 AI 只吐一大段不可控文字。

让模型返回类似：

```json
{
  "summary": "...",
  "risk_points": ["..."],
  "suggestions": ["..."]
}
```

学习：

- JSON 结构；
- 字段验证；
- AI 输出格式错误时的处理。

### 验收

程序可以稳定读取 AI 的多个字段并继续处理，而不是只 `print()` 一段话。

# 五、阶段 C：高中英语 AI 学情助手 v0.1（约 25–35 小时）

这是第一次完整工程验证。

## v0.1 必须完成的链路

```text
上传 / 读取 Excel

↓

↓

↓
绘制成绩分布图
↓
```

## 这一阶段补的知识

按项目需要学习：

- Streamlit（优先作为第一版 Web UI）；
- 表单与文件上传；
- 用户输入检查；
- 程序状态；
- 日志；

- 复杂权限；
- 复杂云架构；

目标只有一个：

> **它真的可以被一个老师拿来用。**

# 七、80–120 小时后的验证标准

不能只问：

> “我觉得编程好玩吗？”

需要分别记录以下指标。

## 1. 兴趣

- 新鲜感消失以后还想不想继续？
- Debug 两小时以后，是“想逃”还是“想弄明白”？
- 是否会主动想到新功能？

## 2. 结构能力

- 是否越来越容易拆模块？
- 是否能快速理解别人代码的结构？
- 是否能发现重复逻辑并主动重构？

## 3. 自主学习

- 能否看官方文档解决问题？
- AI 给出错误代码时能否发现？
- 是否逐渐从“让 AI 替我写”变成“让 AI 和我协作写”？

## 4. 工程耐受力

必须真实经历：

- bug；
- 环境问题；
- API 报错；
- 数据脏乱；
- 重构；
- 前后代码不兼容；
- 做出来后发现设计不好重新改。

如果经历这些以后依然想继续，这是比任何职业测评更强的证据。

## 5. 成果

最终至少有：

- 一个完整 GitHub 项目；
- 清楚 README；
- 可运行版本；
- 数据库；
- AI API；
- 简单 Web UI；
- 一个真实教育场景；
- 多次 commit 历史；
- 能自己讲清楚整体架构。

# 八、职业决策 checkpoint

## 约 30 小时

只判断：

> **工程实现本身是否让我有兴趣？**

不做职业决定。

## 约 60 小时

判断：

- 是否能开始脱离逐行教学；
- 能否独立完成一部分功能；
- 是否愿意继续投入。

## 约 100 小时

正式评估：

### A. 工程兴趣强 + 仍喜欢教育领域

重点考虑：

- AI + 教育应用工程；
- 教育科技产品；
- 现代教育技术 / 教育 AI 相关研究生；
- 用硕士平台放大已有教育经验与技术能力。

### B. 工程兴趣强 + 不想继续绑定教育

重点考虑：

- AI 应用工程；
- 软件工程；
- 完整周期准备计算机 / AI 硕士；
- 武汉等技术岗位生态。

### C. 工程兴趣一般 + 仍愿意教学

重新比较：

- 襄阳市编；
- 更适合的学校环境；
- 教学 + AI 工具作为个人效率增强，而非转行。

### D. 工程兴趣弱 + 教育兴趣也弱

说明当前三条路至少排除了两条，需要重新探索新的职业系统，不强行留在错误路线。

# 九、学习节奏

考虑当前仍承担高三教学，不按“每天必须学”推进。

建议：

- 工作日：45–90 分钟高质量学习 / 项目；
- 空闲日：2–3 小时；
- 连续疲劳时允许暂停；
- 每次结束留下 learning-log；
- 不用补“欠课”，只接着下一步继续。

**目标不是打卡，是持续构建。**
